## 1. Цель и задачи работы

Цель работы — трансформация статического адаптивного веб-сайта интернет-магазина в полнофункциональное интерактивное клиентское веб-приложение на чистом JavaScript (Vanilla JS) без использования сторонних фреймворков и библиотек.

### Реализованные задачи:
1. Вынесение каталога товаров в централизованную структуру данных (`data.js`) — массив из 10 объектов с одинаковым набором типизированных свойств.
2. Реализация динамической генерации карточек товаров через DOM API (`document.createElement`, `classList`, `append`) без статического хардкода в HTML.
3. Разработка живого поиска по наименованию и описанию (событие `input`).
4. Разработка фильтрации по категориям каталога (событие `change`).
5. Реализация сортировки товаров по цене (по возрастанию и убыванию) с обязательной сортировкой поверх поверхностной копии массива (`[...items].sort()`) для предотвращения мутации исходных данных.
6. Обеспечение строгой безопасности вывода данных: все динамические и пользовательские строки выводятся исключительно через свойство `textContent`, что полностью предотвращает уязвимости типа Cross-Site Scripting (XSS).
7. Разработка интерактивной клиентской корзины товаров с сохранением состояния в `localStorage`, изменением количества единиц, удалением позиций, расчётом сумм через `Array.prototype.reduce()` и поддержкой промокодов.
8. Разработка надёжной валидации полей формы оформления заказа (`order.html`) с выводом ошибок непосредственно в разметку страницы (DOM) и полным отказом от встроенного блокирующего диалога `alert()`.
9. Управление модальным окном быстрой консультации через нативный HTML-элемент `<dialog>` с поддержкой закрытия по клику на backdrop и нажатию клавиши `Escape`.
10. Подключение обработчиков событий исключительно через `addEventListener()`.

## 3. Описание JavaScript-файлов и архитектуры

### `js/data.js`
Централизованное хранилище каталога. Экспортирует массив объектов `products` (10 позиций: умные часы, трекеры, умные кольца, аксессуары).
Каждый объект товара содержит строго единообразную структуру:
- `id` (число) — уникальный числовой идентификатор;
- `title` (строка) — наименование товара;
- `category` (строка) — системный идентификатор категории (`wearable`, `audio`, `home`, `power`);
- `price` (число) — актуальная цена в рублях (числовой тип для корректных математических вычислений);
- `oldPrice` (число | null) — прежняя цена для отображения скидки;
- `rating` (число) — средний рейтинг товара (от 1.0 до 5.0);
- `reviewsCount` (число) — количество отзывов покупателей;
- `isAvailable` (булево) — флаг фактического наличия на складе;
- `description` (строка) — краткое описание характеристик;
- `image` (строка) — относительный путь к векторному изображению;
- `badge` (строка | null) — текстовый бейдж («Хит», «Новинка», «Скидка» или null).

### `js/catalog.js`
Модуль рендеринга и фильтрации каталога товаров:
- `createProductCard(product)` — создание DOM-узла карточки товара с помощью нативных методов `document.createElement`, безопасной установки текстовых значений через `.textContent`, навешивания CSS-классов и кнопки добавления в корзину с `data-id`.
- `renderCatalog(items)` — очистка контейнера (`grid.replaceChildren()`) и вставка отфильтрованного набора карточек. Если массив пуст — вызов `renderEmptyState()`.
- `renderEmptyState(container)` — генерация информативного блока с иконкой, пояснением об отсутствии результатов и кнопкой сброса критериев фильтрации.
- `applyCatalogFilters()` — композитная функция, одновременно учитывающая поисковый запрос (без учёта регистра), выбранную категорию и тип сортировки.
- Сортировка выполняется исключительно на копии массива: `[...filtered].sort(...)`, гарантируя иммутабельность глобального массива `products`.

### `js/cart.js`
Модуль управления корзиной покупателя:
- `getCart()` / `saveCart(cart)` — чтение и запись состояния корзины в `localStorage` (ключ `smartpulse_cart`) в формате JSON.
- `addToCart(productId, quantity)` — добавление товара в корзину. Если товар уже присутствует, инкрементирует его количество; при отсутствии — добавляет новую запись с деталями из `products`.
- `removeFromCart(productId)` — удаление позиции из корзины.
- `updateQuantity(productId, newQty)` — изменение количества товара с ограничением от 1 до доступного остатка.
- `calculateCartTotals()` — вычисление суммарной стоимости заказа с использованием метода `Array.prototype.reduce()`. Возвращает общую стоимость без скидки, сумму скидки по промокоду и итоговую сумму к оплате.
- `applyPromoCode(code)` — валидация промокодов (`PROMO10` — 10%, `MIREA` — 15%, `SMART` — 20%) с сохранением скидки в `localStorage`.
- `updateCartBadge()` — сквозное обновление числовых счётчиков количества товаров в шапке сайта на всех страницах проекта.
- `showToast(message)` — всплывающее ненавязчивое уведомление об успешном добавлении товара без блокировки интерфейса.

### `js/validation.js`
Модуль клиентской валидации формы оформления заказа (`order.html`):
- `initOrderValidation()` — перехват отправки формы через `addEventListener('submit', ...)`.
- Вызов `event.preventDefault()` для отмены перезагрузки страницы.
- Проверка обязательных полей:
  - Имя покупателя (не менее 2 символов, только буквы и дефис);
  - Номер телефона (проверка соответствия маске РФ: регулярное выражение `^(\+7|8)?[\s-]?\(?\d{3}\)?[\s-]?\d{3}[\s-]?\d{2}[\s-]?\d{2}$`);
  - Email (валидный синтаксис почтового адреса);
  - Город доставки (не пустая строка);
  - Способ доставки (проверка выбора радиокнопки);
  - Чекбокс согласия на обработку персональных данных.
- `showFieldError(field, message)` — подсвечивание ошибочного поля классом `.is-invalid` и вставка текстового узла с ошибкой в разметку через `textContent`.
- Полный отказ от вызова `alert()` — всё взаимодействие происходит внутри интерфейса.
- При успешной валидации — очистка корзины, генерация случайного номера заказа и отображение карточки успеха.

### `js/modal.js`
Модуль управления диалоговым окном консультации:
- Открытие окна с помощью нативного метода `dialog.showModal()`.
- Закрытие через `dialog.close()` по нажатию кнопок отмены/крестика, клавиши `Escape` и клику вне области содержимого модального окна (backdrop).

### `js/main.js`
Точка входа и координатор глобальных интерфейсных компонентов:
- Инициализация бейджа корзины при загрузке документа (`DOMContentLoaded`).
- Обработка мобильного адаптивного бургер-меню (переключение классов и ARIA-атрибутов).
- Делегирование кликов по статическим кнопкам покупки (`[data-buy-id]`) на главной странице и в карточке товара.

## 4. Описание ключевой интерактивной логики

### Поиск товаров
Поиск реализован на странице `catalog.html` по событию `input` на поле `#catalog-search-input`. При вводе символов строка приводится к нижнему регистру (`toLowerCase().trim()`) и сопоставляется с наименованием (`title`) и описанием (`description`) каждого товара:
```javascript
const query = searchInput.value.trim().toLowerCase();
if (query) {
  filtered = filtered.filter(item => 
    item.title.toLowerCase().includes(query) ||
    item.description.toLowerCase().includes(query)
  );
}
```

### Фильтрация по категориям
Фильтрация выполняется по событию `change` на выпадающем списке `#catalog-category-filter`. Если выбрано конкретное значение категории, массив фильтруется методом `Array.prototype.filter`:
```javascript
const category = categoryFilter.value;
if (category !== 'all') {
  filtered = filtered.filter(item => item.category === category);
}
```

### Сортировка по цене
Сортировка выполняется по событию `change` на селекторе `#catalog-sort-select`. Для исключения мутации глобального массива данных используется оператор расширения (spread-синтаксис):
```javascript
const sortType = sortSelect.value;
if (sortType === 'price-asc') {
  filtered = [...filtered].sort((a, b) => a.price - b.price);
} else if (sortType === 'price-desc') {
  filtered = [...filtered].sort((a, b) => b.price - a.price);
}
```

### Безопасный вывод данных (защита от XSS)
В проекте действует строгое правило безопасности: данные, которые могут быть введены пользователем (поисковый запрос, имя, телефон, адрес, промокод) или динамически получены из источников данных, никогда не передаются в `innerHTML`. При генерации DOM-узлов используется прямое присваивание в свойство `textContent`:
```javascript
const titleEl = document.createElement('h3');
titleEl.className = 'product-card__title';
titleEl.textContent = product.title; // Безопасно: браузер экранирует специальные символы
```

### Расчёт суммы корзины через `reduce()`
Итоговые показатели корзины рассчитываются функциональным методом массивов:
```javascript
const totalBase = cartItems.reduce((sum, item) => sum + (item.price * item.quantity), 0);
const totalCount = cartItems.reduce((count, item) => count + item.quantity, 0);
```

## 5. Самостоятельные доработки сверх базовых требований

1. **Полноценная корзина с `localStorage`:** сохранение выбранных товаров между перезагрузками страницы и переходами по сайту.
2. **Расчёт корзины методом `Array.prototype.reduce()`:** подсчёт базовой стоимости, скидки и итоговой цены.
3. **Механизм промокодов:** валидация промокодов (`PROMO10`, `MIREA`, `SMART`), сохранение применённой скидки в хранилище и динамический пересчёт стоимости заказа.
4. **Управление количеством товаров:** интерактивные кнопки увеличения (`+`) и уменьшения (`-`) количества с проверкой доступного складского остатка.
5. **Сквозной динамический счетчик товаров:** отображение текущего количества товаров в навигационной шапке сайта на всех страницах.
6. **Toast-уведомления:** всплывающее сообщение в правом верхнем углу при успешном добавлении товара в корзину без блокировки действий пользователя.
7. **Расширенное пустое состояние каталога (Empty State):** при отсутствии подходящих под фильтры товаров отображается дружелюбная иллюстрация, поясняющий текст и кнопка «Сбросить фильтры», возвращающая каталог в исходное состояние.
8. **Безопасная валидация без `alert()`:** все сообщения об ошибках отображаются под соответствующими полями ввода с добавлением класса `.is-invalid` и подсказки `.form-field-error`.

## 6. Инструкция по локальному запуску

Проект выполнен на чистом клиентском HTML/CSS/JS и не требует сборки.

После чего открыть в браузере: `http://localhost:8000`.

### Вариант 3. Запуск через npx serve
```bash
npx serve .
```

## 7. Ответы на контрольные вопросы (Раздел 23)

### 1. Что хранится в `data.js`?
В `data.js` хранится централизованный массив объектов товаров `products`. Каждый объект представляет собой структурированную запись о товаре с числовым идентификатором (`id`), названием, категорией, числовой ценой, остатком на складе, рейтингом, описанием, путём к изображению и техническими параметрами.

### 2. Почему каталог удобно хранить как массив объектов?
Массив объектов представляет собой стандартную и наиболее гибкую структуру данных в JavaScript:
- К массиву применимы мощные встроенные методы высшего порядка (`map`, `filter`, `reduce`, `find`, `sort`, `some`, `every`);
- Каждый объект инкапсулирует свойства конкретной сущности по парам «ключ-значение»;
- Такая модель максимально близка к ответу реального REST API / JSON бэкенда, что упрощает масштабирование проекта в SPA.

### 3. Почему у товаров должны быть одинаковые свойства?
Единообразие сигнатуры объектов позволяет писать универсальные функции рендеринга, фильтрации и валидации без необходимости делать индивидуальные проверки на существование свойств (`undefined`). Это предотвращает ошибки во время выполнения (runtime errors) и сохраняет строгий контракт данных.

### 4. Как работает поиск по названию товара?
Пользовательский ввод отслеживается событием `input` на элементе `<input type="search">`. Введённое значение очищается от пробелов методом `.trim()` и переводится в нижний регистр методом `.toLowerCase()`. Затем массив товаров фильтруется методом `.filter()`, проверяющим наличие искомой подстроки в наименовании и описании товара с помощью метода `String.prototype.includes()`.

### 5. Как работает фильтрация по категории?
При наступлении события `change` на выпадающем списке `<select>` считывается его `value`. Если выбрано конкретное значение (отличное от `all`), массив товаров фильтруется методом `.filter()`, который сравнивает свойство `item.category` с выбранным значением.

### 6. Как работает сортировка по цене?
На основе выбранного значения в элементе сортировки запускается метод `.sort((a, b) => ...)`. Для сортировки по возрастанию цены используется функция сравнения `a.price - b.price`, а для сортировки по убыванию — `b.price - a.price`.

### 7. Почему `sort()` лучше применять к копии массива?
Метод `Array.prototype.sort()` мутирует (изменяет на месте) исходный массив. Если применить его напрямую к глобальному массиву `products`, изменится исходный порядок элементов, что приведёт к нежелательным побочным эффектам при последующих фильтрациях и сбросах. Поэтому сортировка всегда выполняется поверх поверхностной копии массива, созданной оператором расширения: `[...items].sort(...)`.

### 8. Что такое DOM?
DOM (Document Object Model, объектная модель документа) — это программный интерфейс (API) для HTML-документов. Браузер парсит HTML-разметку и строит иерархическое дерево узлов (объектов), которыми JavaScript может управлять: создавать, изменять стили, атрибуты, текстовое содержимое и структуру страницы в реальном времени.

### 9. Для чего используется `querySelector()`?
Метод `document.querySelector(selector)` осуществляет поиск и возвращает первый DOM-элемент в документе, удовлетворяющий указанному CSS-селектору (классу, идентификатору, атрибуту или тегу). Если элемент не найден, метод возвращает `null`.

### 10. Для чего используется `createElement()`?
Метод `document.createElement(tagName)` создаёт новый элемент с указанным именем HTML-тега (например, `div`, `article`, `button`, `span`). Созданный элемент находится в памяти JavaScript и может быть настроен (заполнен текстом, классами, атрибутами) до момента добавления в DOM-дерево методом `append()` или `appendChild()`.

### 11. Почему для пользовательских данных используется `textContent`?
Свойство `textContent` записывает переданную строку как обычный чистый текст. Все специальные символы (такие как `<`, `>`, `&`, `"`) автоматически экранируются браузером и не интерпретируются как исполняемый HTML-код. Это гарантирует защиту от атак XSS (межсайтового скриптинга).

### 12. Чем опасен `innerHTML`?
Свойство `innerHTML` парсит переданную строку как разметку HTML. Если вставляемая строка содержит непроверенные пользовательские данные, злоумышленник может внедрить вредоносные теги (например, `<img src="x" onerror="...">` или скрипты), что приведёт к краже сессионных данных, cookie, токенов или подмене интерфейса (XSS-уязвимость).

### 13. Для чего используется `classList`?
Свойство `classList` предоставляет специализированный объект для удобного управления CSS-классами элемента. Его методы:
- `add()` — добавить один или несколько классов;
- `remove()` — удалить класс;
- `toggle()` — переключить класс (добавить, если нет; удалить, если есть);
- `contains()` — проверить наличие класса.
Это безопаснее и удобнее прямой перезаписи строки `className`.

### 14. Для чего нужны `data-*`-атрибуты?
Пользовательские дата-атрибуты (`data-*`) предназначены для хранения вспомогательных служебных данных непосредственно в разметке HTML-элемента без нарушения валидности HTML5. В JavaScript к ним обращаются через свойство `element.dataset.*`. В проекте они используются для связывания кнопок добавления с `id` товара (`data-id="1"`, `data-buy-id="1"`).

### 15. Что такое событие?
Событие (Event) — это сигнал браузера о том, что произошло определённое действие: клик мыши (`click`), ввод текста (`input`), изменение значения (`change`), отправка формы (`submit`), нажатие клавиши (`keydown`) или загрузка страницы (`DOMContentLoaded`).

### 16. Почему обработчики лучше подключать через `addEventListener()`?
Использование `element.addEventListener(type, listener)` является современным веб-стандартом, поскольку:
1. Позволяет вешать несколько независимых обработчиков на одно и то же событие одного элемента;
2. Поддерживает тонкую настройку фаз распространения событий (погружение/всплытие) и опций (`once`, `passive`);
3. Позволяет аккуратно удалять обработчики через `removeEventListener()`;
4. Разделяет вёрстку (HTML) и поведение (JS), в отличие от устаревших инлайновых атрибутов `onclick="..."`.

### 17. Что такое делегирование событий?
Делегирование событий — это паттерн оптимизации, основанный на механизме всплытия событий (event bubbling). Вместо навешивания отдельных обработчиков на множество дочерних элементов (например, на каждую кнопку в каталоге) один общий обработчик вешается на их родительский контейнер, а целевой элемент определяется через `event.target.closest(...)`. Это экономит оперативную память и автоматически работает для динамически создаваемых элементов.

### 18. Для чего используется `preventDefault()`?
Метод `event.preventDefault()` отменяет стандартное поведение браузера, предусмотренное по умолчанию для данного события. Например, при обработке события `submit` формы он предотвращает отправку HTTP-запроса и перезагрузку страницы, позволяя выполнить клиентскую валидацию и обработку через JavaScript.

### 19. Как работает базовая валидация формы?
При попытке отправки формы перехватывается событие `submit`. Скрипт получает значения всех обязательных полей, проверяет их на соответствие установленным правилам (непустое значение, минимальная длина, формат email, телефон по регулярному выражению, факт отметки чекбокса). Если поле не проходит проверку, генерируется понятная текстовая ошибка, а форма не отправляется.

### 20. Почему ошибки формы нужно выводить на страницу, а не через `alert()`?
1. `alert()` является синхронным модальным окном браузера, которое полностью блокирует весь интерфейс и выполнение потока JavaScript до нажатия «ОК»;
2. `alert()` выглядит архаично, не поддаётся стилизации под дизайн сайта и ухудшает UX (пользовательский опыт);
3. Вывод ошибок в DOM под конкретным ошибочным полем позволяет пользователю сразу видеть, где допущена опечатка, и быстро её исправить.

### 21. Какие самостоятельные доработки реализованы?
В проекте реализованы следующие комплексные самостоятельные доработки:
1. Клиентская корзина с сохранением в `localStorage`;
2. Функциональный расчёт сумм корзины методом `Array.prototype.reduce()`;
3. Система промокодов со скидками и пересчётом итоговой стоимости;
4. Интерактивные кнопки изменения количества единиц товара;
5. Сквозной бейдж-счётчик количества товаров в шапке сайта;
6. Всплывающие уведомления (toast);
7. Информативное пустое состояние каталога (empty state) с кнопкой сброса фильтрации;
8. Модальное окно быстрой консультации на нативном элементе `<dialog>`.

### 22. Почему простое копирование методичек не даёт максимальный балл?
Учебные примеры в методических указаниях намеренно упрощены и демонстрируют минимальные базовые паттерны в изолированном виде. Для получения максимального балла студент должен продемонстрировать осознанное владение языком:
- Архитектурное проектирование и разбиение кода на независимые модули;
- Реализацию сквозных пользовательских сценариев (каталог → добавление в корзину → изменение состава → заказ);
- Соблюдение принципов безопасной веб-разработки (защита от XSS через `textContent`);
- Обработку граничных условий (пустая выдача, отсутствие товаров на складе, неверный формат телефона);
- Чистоту и аккуратность кода в соответствии с принципами YAGNI и минимализма.
